# かぎ家計簿

端末の中だけに、暗号化して残す家計簿。iPhone / Android のホーム画面に追加して使う Web アプリ (PWA) です。

- 記録はどこにも送信しません。アカウント登録もサーバーもありません。
- 保存するデータは、金額もメモもカテゴリ名も、すべて AES-256 で暗号化します。
- 外部のライブラリを 1 つも使っていません。ビルドも不要で、置いてあるファイルがそのまま動きます。

## できること

| 画面 | 内容 |
|---|---|
| ホーム | その月の支出・収入・収支、予算の使用状況、日ごとの記録の一覧 |
| 記録の追加・編集 | 支出 / 収入、金額、カテゴリ、日付、メモ |
| 分析 | カテゴリ別の内訳(大きい順)、直近 6 か月の推移(表でも見られる) |
| 設定 | 自動ロック、金額を隠す、パスフレーズ変更、予算、カテゴリ編集、バックアップ、消去 |

## セキュリティの設計

### 何から守るか

| 想定する場面 | 備え |
|---|---|
| 端末を置き忘れた・人に貸した | パスフレーズによるロック。アプリを離れたら即ロック(設定で 30 秒〜5 分の猶予も可)、開いたままでも無操作 3 分でロック。アプリを離れているあいだは中身の代わりにアイコンだけを表示 |
| 保存データを抜き取られた(端末のバックアップ、解析、他のアプリ) | 端末に残るのは暗号文だけ。パスフレーズなしでは読めず、1 ビットでも書き換えれば検出して開かない |
| 画面をのぞかれる | 「金額を隠す」で金額を伏せ字にできる |
| 通信を盗み見られる・外部に漏れる | そもそも通信しない。ページ自身が通信できない設定(CSP `connect-src 'none'`)にしてあり、外部のスクリプト・画像・フォントも読み込まない |
| 悪意のある入力(メモやカテゴリ名、細工したバックアップファイル) | 入力した文字は必ず「文字」としてだけ表示する(HTML として解釈する API を使わない)。Trusted Types で、うっかり使った場合もブラウザが止める。バックアップは中身を 1 項目ずつ検査してから取り込む |
| ロック画面でのパスフレーズの当て推量 | 5 回まちがえると 30 秒、以後 1 分・2 分・5 分…と最長 1 時間まで待ち時間がのびる |
| 故障・機種変更・誤操作によるデータの消失 | 暗号化したままのバックアップファイルを書き出して、端末の外に保管できる |

### 暗号の仕組み

```
パスフレーズ ──PBKDF2-HMAC-SHA-256(60 万回・ソルト 32 バイト)──▶ KEK(鍵を包む鍵)
KEK ──AES-256-GCM で包む──▶ DEK(データ鍵。乱数で生成)
DEK ──AES-256-GCM(毎回あたらしい 96 ビットの乱数 IV)──▶ 家計簿データ全体
```

- ブラウザ標準の WebCrypto だけを使っています。
- 鍵は「取り出し不可」として扱い、JavaScript からは鍵のバイト列を読めません。
- パスフレーズは全角・半角などの違いを吸収するため NFKC で正規化してから使います。
- 鍵導出の条件(回数・ソルト)は追加認証データとして鍵に結び付けてあり、書き換えると解錠に失敗します。
- 平文は 4096 バイト単位に切り上げてから暗号化するので、暗号文の長さから記録件数を細かく推測できません。
- パスフレーズを変更すると、ソルトもデータ鍵も作り直し、データ全体を暗号化し直します。
- パスフレーズはどこにも保存しません。**忘れると、誰にも(開発者にも)復元できません。**

パスフレーズは 10 文字以上が必須で、数字だけなら 16 桁以上、連番・繰り返し・よくある言葉は受け付けません。

### 正直な限界

- **強さはパスフレーズ次第です。** 暗号文を手に入れた相手は、端末の外で好きなだけパスフレーズを試せます。ロック画面の待ち時間はそれには効きません(端末の時計を進めても飛ばせます。画面からの当て推量を遅らせるためのものです)。関係のない言葉を 4 つほどつなげるか、パスワード管理アプリで作った長いものを使ってください。
- **配信元を信頼する必要があります。** Web アプリは、置いてあるサーバーの管理者がコードを書き換えられます。自分で管理する場所に置いてください(下の「スマホで使うには」)。
- **解錠中は守れません。** 解錠した状態の端末を操作される、マルウェアに感染している、改造された端末である、といった場合は対象外です。
- ロックすると鍵とデータへの参照は手放しますが、JavaScript ではメモリの内容を確実に消去することはできません。
- 指紋・顔認証には対応していません。パスフレーズをパスワード管理アプリ(iCloud キーチェーンなど)に保存すれば、その自動入力で代用できる作りにしてあります。
- アプリ切り替え画面での目隠しは、iOS の画面の撮られ方によっては間に合わないことがあります。
- ブラウザのタブのまま使っていると、ブラウザがデータを消すことがあります(特に iPhone の Safari)。ホーム画面に追加し、バックアップを取ってください。

## パソコンで動かす

Python 3 だけで動きます。

```bash
python3 tools/serve.py
```

- アプリ: <http://localhost:8765/app/>
- テスト: <http://localhost:8765/tests/>(開くと自動で実行されます)

開発用サーバーはこのパソコンの中だけで待ち受け、本番と同じセキュリティヘッダーを付けて配信します。

配布物の安全検査(危険な書き方・外部 URL・見えない文字・設定の抜けがないか):

```bash
python3 tools/check.py
```

## スマホで使うには

暗号機能とオフライン機能はブラウザの決まりで `https://` でしか動かないため、`app/` フォルダの中身を HTTPS で配信しています。公開されるのはアプリのコードだけで、記録が送られることはありません。

### いまの配信: GitHub Pages

- アドレス: <https://oppaitoketunara.github.io/kagi-kakeibo/>
- `main` に push すると、GitHub Actions(`.github/workflows/pages.yml`)が `tools/check.py` を実行し、通ったときだけ `app/` の中身を公開します。

### スマホへの入れ方

1. iPhone は Safari、Android は Chrome で上のアドレスを開く。
2. iPhone は共有ボタン →「ホーム画面に追加」。Android はメニュー →「アプリをインストール」(または「ホーム画面に追加」)。
3. **ホーム画面のアイコンから開き直してから**、パスフレーズを決めて使い始める。iPhone では、ブラウザとホーム画面のアプリとでデータが別々になるためです。

### GitHub Pages で知っておくこと

- GitHub Pages はヘッダーを設定できないため、`_headers` の内容は付きません(このファイルは公開もしません)。ページ内に書いた設定(CSP、Trusted Types、枠への埋め込み拒否)はそのまま働きます。
- 同じ GitHub アカウントのほかの Pages サイトは、この家計簿と同じオリジン(`oppaitoketunara.github.io`)になります。そこに置いたページからは、保存データ(暗号文)の読み出しや消去ができます。**出どころのわからないスクリプトを載せたサイトを、同じアカウントの Pages に置かないでください。**
- もっと固くしたい場合は、`app/` の中身を Cloudflare Pages か Netlify に置いてください。この家計簿専用のオリジンになり、`_headers` のセキュリティヘッダーがそのまま付きます。

## バックアップと復元

- 設定 →「暗号化バックアップを書き出す」で、暗号化されたままの JSON ファイルができます。端末の外に保管してください。
- 復元には、そのファイルを書き出したときのパスフレーズが必要です。あとでパスフレーズを変えても、古いファイルは古いパスフレーズで開きます。
- 新しい端末では、最初の画面の「バックアップから復元する」から取り込めます。
- 「CSV で書き出す」は表計算ソフト用で、**暗号化されません**。書き出す前にパスフレーズの再入力を求めます。

## ファイル構成

```
app/                配布するもの(この中身だけを公開する)
  index.html        ページ本体(CSP はここと _headers の両方に書いてある)
  sw.js             オフライン用の Service Worker
  _headers          セキュリティヘッダー(Cloudflare Pages / Netlify 用。開発用サーバーも読む)
  js/crypto.js      鍵の導出・暗号化
  js/vault.js       保管庫(作成・解錠・保存・パスフレーズ変更・待ち時間)
  js/store.js       IndexedDB への読み書き
  js/model.js       データの検査・集計・CSV
  js/passphrase.js  パスフレーズの強さの判定
  js/dom.js         画面を組み立てる安全な部品
  js/app.js         画面の切り替えと自動ロック
  js/screens/       各画面
tests/              ブラウザで動くテスト
tools/              開発用サーバー、検査、アイコン生成
```

## 変更したとき

`app/` の中のファイルを 1 つでも変えたら、配布の前に必ず次を行ってください。

```bash
python3 tools/update_sw.py
```

```bash
python3 tools/check.py
```

そのうえで <http://localhost:8765/tests/> を開き、すべて合格することを確認します。`update_sw.py` を忘れると、利用者の端末には古いファイルが残り続けます(忘れたまま push しても、公開前の検査で止まります)。

公開した更新は、スマホ側ではアプリを一度開き(その裏で新しい版を取得します)、完全に閉じてから開き直したときに反映されます。

## 確認できていること・いないこと

- 確認済み: デスクトップの Chrome(スマホ幅の表示)での全機能、保存データが暗号文だけであること、オフラインでの起動と利用。公開先(GitHub Pages)でも、初回の読み込み、通信を断った状態での起動・保管庫の作成・記録・再解錠を確認。
- 未確認: iPhone / Android の実機での動作(ホーム画面への追加、共有シートでのファイル保存、パスワード管理アプリの自動入力、アプリ切り替え時の目隠し)。
